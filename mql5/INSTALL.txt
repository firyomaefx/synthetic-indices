BREAK100 — install on desktop MT5
=================================

This is the attach guide. README is the project about.

You need
  - Windows PC (or VPS) with MetaTrader 5 desktop. Not the iPhone app.
  - A broker that lists BREAK100 (Mtrading / similar Boom-class synthetic).
  - This repo. Compile on this machine. I cannot ship a working .ex5 for your build.

Chart
  Symbol: BREAK100
  Timeframe: M30
  One chart. Do not run the same EA on M1/M5/M15 if you want one Telegram stream.

As of v2.33 the EA sends NO broker orders in any mode. InpMode (OBSERVE/SHADOW/
DEMO_AUTO/LIVE) still selects the health/mode machinery the HUD and Shadow
ledger read, but none of it reaches OrderSend any more.

Orders are placed only by the Script below, RES-SUP OCO.mq5 -- and as of
v1.01 it trades a LIVE account by default. See its own section.

Copy files
  From this repo:
    mql5\Experts\Break100 Box Trading.mq5
    mql5\Scripts\RES-SUP OCO.mq5
    mql5\Include\Break100\*
    mql5\Indicators\BREAK100_Channel.mq5   (only if you use the old channel strategy)

  Into every:
    %APPDATA%\MetaQuotes\Terminal\<hash>\MQL5\
  matching Experts / Scripts / Include\Break100 / Indicators.

  Or, from the repo's mql5\ folder, one command does pull + copy + compile
  for both the EA and the script, into every terminal it finds:

    .\Install-Break100-Box-Trading.ps1 -Pull -SyncHF

  (-Pull runs 'git pull' first and prints the branch + commit it landed on;
  -SyncHF runs the HF sync after a clean compile, if BREAK100_hf.txt is already
  set up. Both optional; the bare script just copies + compiles what is already
  checked out.)

  Everything ships on master. If your checkout has drifted onto another branch,
  the installer will refuse rather than quietly deploy an old build -- add
  -Branch to move it:

    .\Install-Break100-Box-Trading.ps1 -Pull -Branch master

  The installer prints the versions it actually read off disk, e.g.
    Deployed: EA 2.33  Script 1.01  ->  ...\MQL5
  If those are not the versions you expect, you are on the wrong branch. It no
  longer takes a version on trust -- an earlier build printed a hardcoded
  "v2.33" while deploying v2.31, which is exactly how a stale install went
  unnoticed.

If nothing seems to change after installing
  Run the read-only doctor. It changes nothing and prints what is ACTUALLY
  deployed and compiled in every terminal on this machine:

    .\Check-Break100-Install.ps1

  It separates the three causes that look identical from inside MT5:
    - files never copied here          (source .mq5 missing)
    - copied into a terminal MT5 is not using
    - copied but never compiled        (.ex5 missing or older than the .mq5)

  MT5 loads the compiled .ex5, never the .mq5. A stale .ex5 keeps the old EA
  running no matter how often you refresh Navigator.

  WHICH FOLDER COUNTS: the installer scans %APPDATA%\MetaQuotes\Terminal\*.
  A portable or Microsoft Store install can keep its data somewhere else. The
  authority is MT5's own  File -> Open Data Folder.  If that path is not one
  the doctor lists, install straight into it:

    .\Install-Break100-Box-Trading.ps1 -TerminalDataPath "<that path>"

Compile
  If you used the .ps1 above, this is already done -- check its output for
  '0 error' on every file. Otherwise, by hand:
  F4 MetaEditor → open Break100 Box Trading.mq5 → F7. Log must say 0 errors.
  Repeat for RES-SUP OCO.mq5.
  Version in the Navigator / Experts tab: 2.33 (EA), 1.01 (Script).
  Close MetaEditor. In MT5 Navigator: right-click Experts → Refresh, and
  right-click Scripts → Refresh.

Attach (EA -- detection, HUD, Telegram, Shadow ledger; sends nothing)
  1. Open BREAK100 M30.
  2. Drag Break100 Box Trading onto the chart.
  3. Inputs: InpStrategy = BOX_M30, InpMode = OBSERVE, InpBoxTF = M30,
     InpTelegram = true, InpDrawLevels = true, InpCapture = true.
  4. Experts log: B100 Telegram ON  chart=M30

Run the script (RES-SUP OCO -- THIS is what places orders, real money by
default on a real account)
  1. Wait for RES/SUP to appear on the chart (the EA draws these once a box
     arms).
  2. Navigator → Scripts → drag 'RES-SUP OCO' onto the chart.
  3. Its input dialog opens every time -- check InpAllowLiveTrading and
     InpLots before you click OK. Demo account first, always.
  4. It places a BUY STOP + SELL STOP off RES/SUP with SL/TP already
     attached, watches for a fill, cancels the sibling, then exits. Read
     the manual test procedure in its own header comment before going live.

Telegram
  File (not in git):
    %APPDATA%\MetaQuotes\Terminal\Common\Files\BREAK100_telegram.txt
  token=...
  chat=...
  Example: mql5\BREAK100_telegram.txt.example
  MT5 → Tools → Options → Expert Advisors → allow https://api.telegram.org
  Alerts: WATCH, ENTRY, TP, SL (replies). Signal 1,2,… from 06:00 GMT.
  6h status is a short emoji card.

Hugging Face (optional, free tier)
  Common\Files\BREAK100_hf.txt
    token=hf_...
    dataset=yourname/break100-boom
  python tools\break100_hf_train.py
  python tools\break100_hf_sync.py
  15-min task: tools\Install-BREAK100-HF-Sync.ps1
  Need 16+ quality=1 rows. Not a profit claim.

After fill
  Chart shows dotted SL / ENTRY / TP1 / TP2 / TP3 with the price on each line.
  Not a Fibonacci object.

Do not
  - Commit telegram or HF tokens
  - Run RES-SUP OCO.mq5 on a live account before a full demo fill+cancel cycle
  - Treat SKIP / runner policy as an edge
  - Claim this system is profitable -- research/BACKTEST_RESULTS.md measures
    -4.90% ROI / -0.164R over 3.56M ticks, best of 20 configs at t=+0.12
    against the ~2.45 bar it needed to clear
